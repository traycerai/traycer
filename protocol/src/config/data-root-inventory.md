# Data-root path inventory (OSS repository)

Every literal or indirect construction of a Traycer home path in this
repository, classified against the data-root contract in
[`data-root.ts`](./data-root.ts). Update this table in the same change that
adds, moves or removes such a construction.

Contract, in one paragraph: `traycerDataRoot()` is the only resolver. It reads
`<os.homedir()>/.traycer-bootstrap/location.json`; without a record the root is
`<home>/.traycer` exactly. An unreadable, malformed or invalid record, or a
selected root that is not an existing directory, throws `DataRootError` - there
is no fallback root. `TRAYCER_DATA_DIR` is setup-only input
([`data-root-setup-input.ts`](./data-root-setup-input.ts)); runtime never reads
it. Consumers call the resolver at use time and never cache it in a module-scope
constant.

Dispositions:

- **root** - relocatable Traycer data; derived from `traycerDataRoot()`.
- **bootstrap** - fixed at `<home>/.traycer-bootstrap`; never relocated.
- **repo-local** - a repository's own `.traycer/` folder (workspace
  configuration); unrelated to the data root; unchanged.
- **excluded** - OS, Electron or third-party provider state; outside the
  contract; unchanged.
- **dev-tooling** - developer/test scripts that assume the default layout;
  unchanged, and unsupported on a machine with a location record.
- **doc** - comments, user copy and documentation that describe the default
  layout; no behaviour.
- **owner: 718-n** - relocatable, but rewriting it belongs to the named ticket
  of the issue #718 breakdown.
