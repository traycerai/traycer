# Profile Creation Honesty — Deviations

- **Task 3 — resolution path:** Plan said to reuse `use-resolved-workspace-folders-query.ts` to map paths → `WorkspaceFolderInfo`. That hook actually joins the *existing* workspace-store folders against host `resolvePathsByRepoIdentifiers` and returns `ResolvedFolder[]` for display — it does not resolve arbitrary profile paths into infos. Profile folders only store `{ path, hostId }`. Bridge projects them synchronously via `profileFoldersToWorkspaceFolderInfos` (`name` from path, `repoIdentifier: null`). No network mock needed; pure mapping is always "ready". Why: follow the code; full `prepareFolders` round-trip would reintroduce async host coupling for a path set the user already chose.
- **Task 5 — unassigned predicate:** Plan text used `!allProfiles.some(p => p.assignedEpicIds.includes(epicId))` (manual assignment only). That would also list folder-owned epics as Unassigned. Implemented with `!profiles.some(p => profileOwnsEpic(...))` so rescue is true orphans only; matches the Task 5 test cases (A via folder, B via assignment stay out of Unassigned).
- **Task 5 — card membership:** Plan said `itemVisibleInProfile` for per-profile cards. That is fail-open for unscoped epics (visible in every profile), so Unassigned epics would also appear under every card. Cards use `profileOwnsEpic` (assignment or folder match) instead.
- **Task 9 — which content path carries the prelude:** Create-time injection (`prependPlainTextToComposerDoc`) writes plain paragraphs into the composer `JsonContent` doc, so production messages typically store the prelude on `structuredContent` (rendered by `ComposerContentRenderer`). ~~v1 strips only the string path~~ **RESOLVED in review:** `stripOrchestrationPreludeFromDoc` now removes the marker-owned block span from structured docs (whole-line blocks only, fail-open otherwise), applied to the bubble body, the clipboard text, and the copy overlay. The editing surface keeps the stored doc untouched.
