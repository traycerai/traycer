<Update label="v1.5.0">
Profile sync, native subagent continuation, and protection against incompatible task-store rollbacks.

* **Profile sync** — transfer supported Claude Code, Codex, Grok, and Antigravity sign-ins directly between your Hosts. Synced profiles carry refreshed sign-ins between devices, and a source Terminal account arrives as a managed profile without replacing the destination's Terminal account.
* **Subagents** — continue a completed Claude Code or Codex native subagent in its own chat on the same Host, sharing the parent's workspace. Repeating the action opens the chat already created for that subagent.
* **Host rollback** — compatibility checks now include the local task store. A rollback to a Host that cannot read it is refused unless you explicitly accept the temporary loss of access to local tasks; the task store is not deleted.

See the [GitHub release](https://github.com/traycerai/traycer/releases/tag/host-v1.5.0).
</Update>

<Update label="v1.4.2">
Reliable Codex terminal agents and less background work for long chats, artifact history, and deleted worktrees.

* **Codex terminal agents** — starting, resuming, and forking work with current Codex versions. Permissions and additional writable folders are passed correctly, including on a reopen. The bundled Codex is updated to 0.159.1.
* **Long-running chats** — saving new activity no longer grows more expensive as consecutive agent turns accumulate without another user message.
* **Artifact history** — capturing an unchanged artifact no longer writes to the version journal, reducing background disk activity.
* **Worktrees** — checks avoid unnecessary Git launches into deleted worktrees and limit filesystem work on unresponsive mounts.
* **Provider sign-in** — cancelling one attempt leaves a shared login running for the other attempts that still need it.
* **Notifications** — a shell-output notification waiting for delivery carries its chat, so it can open the right conversation.
* **Diagnostics** — requests that have ended are no longer logged as credential failures at ERROR level.

See the [GitHub release](https://github.com/traycerai/traycer/releases/tag/host-v1.4.2).
</Update>

<Update label="v1.4.1">
Fixes for provider sign-in, Copilot startup, Task renames, and background resource cleanup.

* **Provider sign-in** — failed account switches no longer report success by falling back to the old account. Refusals and account-verification links are surfaced.
* **Antigravity** — sign-in can continue after the request that started it ends. Custom CLI paths are refused because the agent needs its managed ACP server.
* **Copilot** — opening a session scans the managed skills folder instead of the whole Traycer data folder, avoiding startup timeouts on machines with many worktrees and chats.
* **Task renames** — a rename interrupted by reconnecting storage is retried, and History metadata catches up after the connection returns.
* **OpenCode and downloads** — finished event streams and abandoned downloads close their connections instead of leaving unread data accumulating in network memory.
* **Background workers** — if the Host's working directory is removed while it runs, the Host recovers to an available home folder so replacement workers can start again.
* **Artifact watching** — shutting down a Task safely contains late file-watcher errors.

See the [GitHub release](https://github.com/traycerai/traycer/releases/tag/host-v1.4.1).
</Update>

<Update label="v1.4.0">
Model routing, Auto mode, agents that work across your machines, Antigravity, and rebuilt storage.

* **Model routing** — when a turn fails on a usage limit, a sign-out, a billing problem, or an unavailable provider or model, the Host can move the chat to a model in the same tier. For a usage limit, a sign-out or a billing problem it can also switch to another account for the same provider, and for a usage limit it can wait for the reset and retry. After a switch, it asks you, or switches back on its own if you choose, once your preferred account or model is available again. Tiers match models by name pattern.
* **Auto mode** — a judge reviews commands before they run and asks you about the ones it won't approve; edits to sensitive files such as git config and hooks still ask you. By default the judge runs on Traycer Inference and falls back to the conversation's own provider and account, and Claude Code conversations can use Claude Code's own classifier instead. A repository's `.traycer/auto-policy.md` can add restrictions but never loosen yours, and the Host keeps a log of recent decisions.
* **Your machines, working together** — agents can list your machines, create and message agents on them, run a command on another machine, copy files between machines, and forward a port between their own machine and another of yours. A remote agent's browser can open in the desktop app you messaged it from.
* **Across Tasks** — agents can list your Tasks, message and manage agents in your other Tasks, and search your chat history on their machine.
* **Chat search** — the Host indexes the prompts, agent replies, and notices of your chats on it, across Tasks, for full-text search. Terminal-agent chats, reasoning, and tool output are not indexed.
* **Remote sign-in** — sign a remote Host in to Codex, Grok, or Kimi with a sign-in link and a one-time code, or to Claude Code by pasting a code, from the machine you're using. Signing in to an account no longer interrupts chats already running on it.
* **Antigravity** — Google's Antigravity coding agent runs through its official ACP server. Models are read live from your account, effort levels are grouped under one model, and, with a Google sign-in, 5-hour and weekly limits are reported for each model group. It is not available on Intel Macs.
* **Storage** — database work runs asynchronously instead of blocking the Host, and chats are stored as rows instead of one document that is rewritten whole. The Host also holds less in memory, and on macOS it no longer holds on to freed large memory blocks.
* **Version history** — the Host keeps version history for specs, stories, tickets, and reviews. It is on by default and stored separately from checkpoint snapshots, so clearing those doesn't affect it.
* **Labels** — Task labels are saved to the cloud, with edits queued across restarts and retried. Earlier imports the Host still has a record of also get the **Imported** label.
* **Worktrees** — optional automatic cleanup, off by default: once a day the Host deletes worktrees that have been inactive longer than the limit you set and whose work is merged, pushed, or never moved from its starting commit, with no uncommitted changes, open PR, or active session. Anything it can't verify is skipped. Deleting a worktree also says why a busy agent is holding it.
* **Grok** — editing or forking from an earlier message now continues Grok's own session instead of starting a new one, plus image attachments and permission prompts that go through Traycer.
* **Fixes** — an open chat reconnects on its own through a planned Host restart, Stop can now end a turn whose provider has stopped answering, terminal agents' launch arguments on Windows keep their backslashes and quotes, shell commands agents run on a Windows Host actually run, and a terminal whose folder was deleted reopens in your home folder.
</Update>

<Update label="v1.3.0">
Agent-controlled browsers, session import, and much faster Tasks.

* **Browser sessions** — agents can open and drive browser sessions, with sign-ins stored encrypted and carried across Hosts.
* **Session import** — bring Claude Code, Codex, and OpenCode sessions into Traycer.
* **Mobile app** — the Host serves the Traycer mobile app.
* **Faster Tasks** — Tasks open from local data in a fraction of the time, long chats load in windows, and memory use is reported accurately.
* **Comments as files** — agents read comment threads as files beside each artifact and resolve them by editing their status.
* **Worktrees** — deleting a worktree first stops whatever is using it, sweeps ask for consent before tearing anything down, and deletion rows say why they failed.
* **Providers** — the Reasonix coding agent is now available; OpenCode reaches parity with Claude; Copilot, Qwen, Grok, and the OpenCode family can be steered mid-turn; Grok gets background work and managed profiles; and sign-in terminals launch the CLI for Qwen, Droid, OMP, and OpenCode.
* **Harness enablement** — harnesses are enabled once you are signed in, then stay on or off as you set them.
* **Shells** — choose per command whether it relaunches when the Host restarts.
* **Updates** — updates are tracked through to completion, and explicit downgrades are supported.
* **Reliability** — fixes for artifacts lost after a storage replacement, a slow git process taking down a Task, and a Windows Host crash.
</Update>

* **Communication Graph** — messages between agents are recorded and streamed for each Task.

* **Agents** — fork an agent, stop its whole runtime rather than just the turn, and create agents without a folder.
* **Skills** — imported skills are stored once and shared across providers.
* **Git** — edit files in place from the diff, and read GitHub pull requests and issues for mentions.
* **Worktrees** — branch prefixes can be set per repository, and recent workspace folders are remembered.
* **Fixes** — Claude profiles no longer sign themselves out, idle Hosts stay quiet, and restart checks ignore idle terminals.

<Update label="v1.0.0">
First public release of the Traycer Host — the local runtime that powers Traycer. It runs the coding agents, terminals, and Tasks behind Traycer Desktop, entirely on your machine. You do not install the Host directly; the Traycer CLI downloads, verifies, and supervises it for you.

* **Runs agents locally** — executes your chosen coding agents directly on the repositories you are working in.
* **Local storage** — stores Tasks, conversations, plans, and history in a local SQLite database.
* **Terminals, files, and worktrees** — manages terminals, files, and git worktrees, and exposes a versioned protocol that Traycer Desktop connects to.
* **Managed service** — registers with your OS service manager (launchd on macOS, systemd user on Linux), starting with your session and supervised automatically.
* **Agent backends** — Claude (Claude Code), OpenAI Codex (with reasoning depth and optional Fast tier), Cursor, OpenCode, and Traycer Inference, selectable per Task.
* **Skills** — ships Traycer's versioned, integrity-checked workflows for brief, plan, breakdown, execution, and review.
* **Privacy** — does not log secrets or source code.
* **Platforms** — macOS (Apple Silicon and Intel) and Linux (x64), delivered as a signed single-file runtime with no separate Node or Bun install. Builds are verified by SHA-256 checksum and minisign signature before installation.
</Update>
