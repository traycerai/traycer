## Task

A **Task** is the top-level container for a piece of work in Traycer. It maps to an outer Task tab and keeps related agents, panels, artifacts, terminal sessions, browser tabs, files, git diff, and pull requests together.

## Workspace Folder

A **workspace folder** is a local code folder or repo that Traycer can work against. A Task can be associated with one or more workspace folders.

The composer shows one summary chip with the primary folder, its branch, and a `+N` badge for additional folders. Open that chip to see each folder and its run location, or choose **Add folder** to attach another folder.

When a workspace folder is a git repository, Traycer can run agent work in the folder itself or in a git worktree. See [Worktrees](/concepts/worktrees).

## How a Task Is Organized

| Part | Purpose |
|---|---|
| **Workspace folders** | The local code folders Traycer can inspect or modify. |
| **Panels** | Nine sidebar navigators: Agents, Terminals, Browsers, Artifacts, Git Diff, Pull Requests, File Tree, Sharing, and Comments. |
| **Canvas tabs** | The work surfaces opened from panels, such as agents, terminals, browser tabs, artifacts, file previews, and diffs. |
| **Artifacts** | Durable specs, tickets, stories, and reviews that preserve intent and progress. |

Learn the sidebar panel list in [Panels](/panels). For how artifacts and planning skills work inside a Task, see [Artifact workflow](/concepts/artifact-workflow).
