# Host-update contender inventory

This is the Ticket 02/03 inventory of every production path that can mutate the
host install/stage tree or stop, start, register, deregister, or activate the
host. It is intentionally checked in beside the enforcement boundary: adding a
new mutator requires adding it here **and** routing it through that boundary.

## Boundary policy in this shadow release

`update-attempt.lock` is outermost and the existing `cli-lock` remains the
inner installation/service lock. A real attempt capability is an issued,
currently-owned update-attempt handle; it is the only authority an enabled
schema-v2 executor may use for an update mutation.

Schema-v2 execution is deliberately not enabled in this ticket. Existing
callers therefore use a named legacy-shadow or maintenance admission below:

| Admission                        | Active/parked valid attempt                                                                                                                                                                                                                  | Absent or terminal attempt                                                                             | Faulted record (`corrupt`, `unreadable`, unsupported) |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| `legacy-update-shadow`           | yield; no side effect                                                                                                                                                                                                                        | preserve the legacy operation, under both locks                                                        | fail closed; no side effect                           |
| `stage-maintenance`              | yield; retain staged data                                                                                                                                                                                                                    | run short reconciliation/prefetch mutation                                                             | fail closed                                           |
| `uninstall-maintenance`          | refuse; retain evidence and install tree                                                                                                                                                                                                     | run the explicit user removal                                                                          | fail closed                                           |
| `service-maintenance`            | refuse; do not stop/restart/register a possibly updating host                                                                                                                                                                                | run the explicit service operation                                                                     | fail closed                                           |
| `desktop-activation-maintenance` | refuse; no bootout/re-register                                                                                                                                                                                                               | run Desktop's existing activation/repair section                                                       | fail closed                                           |
| `runtime-repair-maintenance`     | refuse; no kill/restart                                                                                                                                                                                                                      | run the doctor-confirmed repair                                                                        | fail closed                                           |
| `recovery-maintenance`           | allow only the independent recovery edge under the canonical lock; `applying`, `waiting-to-activate`, and the placed-byte `preparing/activate` handoff are stop-only; post-restart `restarting`/`verifying` may restart the installed target | restart the current service target                                                                     | fail closed                                           |
| `attempt-executor`               | acquires the canonical lock, then may claim/recover only through the capability-consuming intent facade; an active unheld record is reconciled from lock-scoped install/stage/running evidence before any write                              | may create only through the same intent facade; retained terminal evidence remains ordinary core input | fail closed; no claim, recovery, or side effect       |

Every named maintenance or legacy admission remains unable to create, resume,
advance, or prune a schema-v2 record. `attempt-executor` is the sole
exception: it still exposes neither a raw handle nor a caller-supplied next
record, and its `recover` write is recomputed from canonical bytes under the
held lock. The CLI cohort is currently shadow-only, so no released command
selects it and the legacy marker/executor remain authoritative until Ticket 07.

## Exclusions

Registry download-cache ownership, logs, credentials, user preferences, and
read-only host-status/lifecycle probes are not install-tree or restart
mutations. They remain outside this boundary. Existing externally-managed
service detection keeps refusing internal registration takeover unless the
caller explicitly requested the existing takeover flow; Ticket 02 does not
change that authority decision.

`scripts/install-desktop.js`, `scripts/cleanup-legacy-desktop.js`, and the
`dev-desktop` helpers are explicitly **developer-local legacy tooling**: they
package the local channel or remove only pre-NP-8 artifacts, are not invoked by
the cloud install/uninstall entry points, and do not operate a cloud-slot
executor. They remain no-cutover exclusions, not unnamed maintenance
exemptions. Any production promotion of one of those flows must first add a
named contender admission and an inventory row.
